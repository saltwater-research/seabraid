# THE PICK RULE, as a table: what one pick, and one row of picks, may be.
#
# OWNER: src/picks.rs owns the rule; this file is the one place its cases are written down, so the Rust core, the
# ggml adapter and the Python reference provider are all held to the SAME rows instead of each keeping a private
# copy of the rule that only a fuzz test (Python) or nothing (ggml) ever compared.
# WHY a table and not three test suites: the rule was restated in the runtime, the ggml adapter and the reference
# provider (and again in the Strata adapter); a fourth hand-written list of cases would be a fourth place to forget.
# CONSUMERS (each fails when one row below is altered):
#   src/picks/tests/golden.rs                   kind AND pick index, through picks::check; also proves the wide rows
#                                               took the sort path, and reads the two `limit` lines
#   adapters/ggml/test_routes.c                 kind, through seabraid_ggml_routes_fault (not the partial=0 rows that use
#                                               a skip: the adapter always advertises PARTIAL_ROUTES), plus both
#                                               `limit` lines
#   bindings/python/tests/test_pick_golden.py   valid or INVALID, through ReferenceSession.submit (it names no kind)
# FORMAT: one `case` per line, fields split by " | ":
#   case <name> | <experts> <partial 0|1> <top_k> | <ids, a whole number of rows of top_k> | <weights> | <verdict>
#   <weights>: `-` (every weight 0.5) or `<pick>=<value>` overrides; value is nan, inf, -inf, -0 or a decimal.
#   <verdict>: `ok`, or `<kind>@<pick>` with kind range | skip_weight | finite | repeat, and <pick> the 0-based
#   index of the FIRST defect of any kind in pick order (at one pick: range, then finite, then repeat).
#   `limit <name> <n>` lines: constants two layers must agree on (see the consumers).
# Alter a row and its consumers fail; add a row and all three are held to it at once.

# Rows wider than narrow_row repeat-check by sorting, narrower ones by scanning; both layers must change strategy at
# the same width. max_picks is the ggml graph's own cap on top-k, recorded here so it cannot drift unseen.
