### seabraid-dsv41 first live run (run E) - raw
Build dsv41/v1 c9823b0 (8 patches applied clean, tree 21f4e766), R9700 HIP main + RTX 3090 CUDA helper.
`kl_gate_dsv41.sh`, 2 segments x 1000 ids, `--window 1` (every token on the helper's decode path),
ENGINE_ARGS `--max-context 131072 --eos 1 --vision off --dspark auto --dspark-conf 0.65 --reserve-mib 900`,
SHIFT_ARGS `--vram-experts 0.085`. Max temperature: 3090 48 C, R9700 77 C.

It works:
- Helper: 2,843 experts, 22.78 GiB, filled in 12.4 s. Score arm: 54,130 helper requests, 83,625 picks, 3,057 ms waiting on the
  helper in all, 0 CPU fallbacks. tok/s arm: 3,395 requests, 193 ms waiting, 0 fallbacks.
- Speed, same 32-token prompt, 128 tokens decoded (DS4_NO_EOS): Strata integration 10.08 tok/s vs stock 6.17 tok/s in the same session
  (x1.63). CPU lane 5,635 vs 10,467 of 25,400 picks. The adaptive cache moved 843 (Strata integration) / 1,001 (stock) experts. The
  stock figure is below the 7.4 baseline: the 7.4 run used other flags and a different prompt, so compare 10.08 with 6.17.

KL (kl_dsv41.py, 1,998 positions):

| arm vs stock1 | KL(top32) mean | p99 | max | top-1 |
|---|---|---|---|---|
| stock2 (noise) | 0.00646 | 0.07274 | 1.579 | 96.60% |
| Strata integration | 0.01820 | 0.26224 | 1.776 | 93.74% |
| placement shift (2,838 -> 197 VRAM experts) | 0.02001 | 0.24034 | 3.400 | 93.24% |

Verdict: FAIL (all three thresholds) and NOISE-DOMINATED: the engine is NOT deterministic here, because the adaptive cache
moves about 1,000 experts per run. SPREAD: mean x0.91, p99 x1.09, top-1 +0.50 pt vs the shift arm, labelled WORSE on p99
alone. By KL, Strata integration moves the logits about as much as stock's own move of a similar number of experts between GPU and CPU.

Perplexity per segment, computed from the tsv files (exp of minus the mean target log-prob, 999 positions each):

| arm | seg 0 | seg 1 |
|---|---|---|
| stock1 / stock2 | 4.4086 / 4.4119 | 23.402 / 23.070 |
| placement shift | 4.4338 (+0.6%) | 23.643 (+1.7%) |
| Strata integration | 4.5424 (+3.0%) | 24.069 (+3.6%) |

Percentages are against the stock pair's mean. Unlike KL, perplexity is directional: Strata integration is worse than stock AND worse than
the shift arm in both segments. That points to a systematic difference between the helper's rows and the CPU lane's rows for
some experts, not to rounding noise. Activation rounding is ruled out (the helper latches DS4_IQ_Q8K from kSpecActQ8K,
`compat/strata/strata-ext/src/dsv41_exec.cu:193-199`, matching the CPU lane's Q8_K). The synthetic-weight parity test on the 4080
(nrmse ~1e-7) did not use real pack weights.

Doc bug found: `--vram-experts` is a fraction of free VRAM (ds4_model.cu room = free * vram_experts), not a count;
fixed in dsv41/v1 141a726, which also adds SCORE_ARGS so the KL arms can run with `--no-expert-cache` while tok/s keeps it.

## 7. Independent review (read-only, 2026-11-07)
The reviewer
spot-checked 5 claims against the code and logs, and all held. These findings change the plans:
- **dsv41 arms were not independent.** The engine rewrites `expert-profile.bin` at exit (ds4_main.cpp:2010) unless
  `--profile-readonly` (ds4_main.cpp:2528) is passed; it was not, so each arm inherited the previous arm's placement. Fix:
  `--profile-readonly` in every arm.
- **Stale invariant.** ds4_model.cu:9702 says both lanes round alike by default, but `iq_q8k()` is opt-in (ds4_gguf.cu:266-273):
  stock's GPU lane rounds per-32 while the CPU lane uses Q8_K. Together with the adaptive cache this explains the stock noise
  (0.0065). `DS4_LANE_CHECK=1` exists (ds4_model.cu:10681, :10731): one expert of each format through both lanes at load, which
  is the stock reference for GPU-vs-CPU parity.
- **The dsv41 perplexity loss is real on paired statistics.** Signed dlogp (stock - Strata integration, positive = Strata integration worse):
  +0.0290 +/- 0.0088 (t 3.3) vs stock1, +0.0358 (t 4.35) vs stock2, the same sign in both segments. The placement shift is
  +0.008 (t 0.9, not significant). By design Strata integration should be no worse than a placement shift; it is 3.6x larger. This points
  to a helper-path numerics bug.
- **The thresholds 0.0025 / 0.039 / 98.4% are not a tolerance:** they are one 441-token Qwen stock-vs-stock noise sample
  (DESIGN-LOG.md:119-120). A verdict should rest on paired dlogp +/- SE over interleaved arms.
- **Qwen hot-share "-1 to -4% per window" is inside baseline drift.** The same H0 config with byte-identical text measured 26.2 ms/window
  in an earlier run vs 27.4 in a later run (4.5%). The Qwen KL arms ran `--short-read` with 11,110 experts on the mmap fallback (27-28 GB read
  from slower storage per 442-token prompt), not the default decode path. H1 has LOWER perplexity than H0 (dlogp -0.075, t -2.6).
- **dsv41 x1.63 is I/O relief, not compute:** disk reads 453 -> 274 MB/token, CPU-lane wait 138 -> 78 ms/token, helper wait 1.5
  ms/token. The 3090 acts as a 22.8 GiB cache in front of slower storage. More host RAM would do the same with no
  cross-vendor numerics risk.
- **Patch hygiene.** There were two different 0009s in two places (now renumbered: dsv41 LINK_CHECK keeps 0009, Qwen phase 1
  becomes 0010). kVersion stayed 6 with new per-token use for Qwen: v6 already defines kOutPerToken, and a pre-phase-1 helper
  answering per-pick is refused by out_mode, not silently mixed. Phase 1 keeps Qwen's k == 10 and H hard-coded (Qwen-only).
- **Strategy.** A per-layer request/sync channel caps the 3090 at about 25% busy. Phase 1 recovers up to about 3 ms per window, then the
  R9700 is the floor. Symmetric GPUs need a cross-process layer pipeline (activations across the boundary): a different
  project. Expert splitting is not worth starting before the per-layer sync is gone.
