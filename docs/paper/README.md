# The Seabraid paper (expert braiding)

LaTeX source for the planned Zenodo preprint and later arXiv cs.DC submission.
The author is Saltwater Research LLC. The paper draws on the
[technical note](../TECHNICAL-NOTE.md), the [research log](../RESEARCH-LOG.md), and the
[Strata integration results](../../compat/strata/README.md). Build and review
the PDF from this source before submitting it.

| File | What |
|---|---|
| `seabraid.tex` | The paper (article class, `tikz`, `booktabs`, `hyperref`, `lmodern`; no exotic packages) |
| `refs.bib` | References. Only fields recorded in this repository are filled in |
| `figures/fig-weight.tex`, `fig-racks.tex`, `fig-archs.tex` | Vector TikZ figures, generated by `figures/gen_figures.py` (edit the generator, then run it) |
| `figures/fig-pyramid-live.tex`, `fig-l1-moves.tex` | Live-run L1 figures, generated by `figures/gen_live_figures.py` from `../img/data/l1-*.csv` (the SVG twins in `../img/` come from `../img/gen_l1_figures.py`) |
| `figures/fig-system.tex` | The system diagram (hand-written TikZ) |
| `build.sh` | Builds the PDF and the arXiv tarball into a directory outside `docs/paper/` |

## Placeholders to fill before submitting

- `\product` (top of `seabraid.tex`): the product name. **Seabraid is the final name** (decided 2026-11-21); a future rename is this one line
  in the paper, plus the product name inside `../../.zenodo.json`, `../../CITATION.cff` and `figures/gen_figures.py` (one
  string, "Expert braiding (Seabraid)"; rerun the generator).
- `\REPOURL`: the repository URL, once it exists. `\DOI`: the DOI the archive assigns (Zenodo gives one on
  deposit; paste it in and rebuild before the arXiv upload).
- `refs.bib`: authors and full titles of the arXiv entries were not recorded in the repository, so they are left out. Add them from each
  arXiv abstract page if you want complete entries.
- `../../.zenodo.json` describes the software deposit. Add a related publication identifier once the preprint has an assigned DOI.

## Build

Needs `pdflatex` and `bibtex` from a TeX Live (packages: `tikz`/`pgf`, `booktabs`, `hyperref`, `lmodern`, `xcolor`,
`geometry`). From a POSIX shell (Git Bash on Windows works):

```bash
docs/paper/build.sh [BUILD_DIR]     # default: ${TMPDIR:-/tmp}/seabraid-paper-build
```

It writes `seabraid.pdf` and `seabraid-arxiv.tar.gz` into `BUILD_DIR`, and fails loudly (exit 2) if there is no TeX engine.
It exits 1 on a LaTeX or BibTeX error, an undefined reference or citation, or (when `pdffonts` exists) a font that is not
embedded. Then read the PDF: expected length is 6 to 10 pages; check the four figures render and the tables fit the page.

## arXiv

- Upload the **source**, not the PDF: `seabraid-arxiv.tar.gz` holds `seabraid.tex`, `seabraid.bbl` and `figures/*.tex`.
- The `.bbl` must be included. arXiv does not run BibTeX for you reliably, and a `.bib` alone is not enough; `build.sh`
  leaves `refs.bib` out and ships the `.bbl` made from it. Rebuild after any change to `refs.bib`.
- Choose cs.DC as the primary category (cs.LG or cs.AR as cross-lists if wanted). A first-time submitter needs an endorser.
- Test the tarball once by unpacking it into an empty directory and running `pdflatex` twice there.

## Zenodo (paper)

Upload the PDF (and optionally the tarball) as a new upload with these fields:

| Field | Value |
|---|---|
| Resource type | Publication / Preprint |
| Title | the paper's title |
| Creators | one organisation: Saltwater Research LLC |
| License | Creative Commons Attribution 4.0 International (CC-BY-4.0) for the paper (the software stays Apache-2.0) |
| Keywords | mixture-of-experts; expert braiding; cross-vendor expert parallelism; inference; heterogeneous GPUs; expert placement; CUDA; ROCm |
| Related identifiers | the repository URL, relation `isSupplementTo`, resource type Software |
| Version | the software version printed on the paper's title page |
| Description | the abstract |

The software record is separate: with Zenodo's GitHub integration enabled for the repository, a release is archived using
`../../.zenodo.json` (type software, Apache-2.0). After both records exist, add each one's DOI to the other
(`isDocumentedBy` in `.zenodo.json`; `isSupplementTo` on the paper), then rebuild the paper with `\DOI` filled in.

Nothing here has been uploaded or published; those steps are the maintainers'.
